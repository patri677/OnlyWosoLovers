## 发现的问题

以下保留首次复现的历史记录，**R1–R5 均已修复**：

- R1：头像地址拒绝不安全字符，节点及资料弹窗的头像属性统一转义；相关关系 ID 的 HTML 属性也转义，兼顾直接编辑尚未保存的内容。
- R2：localStorage 与 IndexedDB 恢复均复用共享数据校验；损坏缓存不覆盖内嵌有效图谱，不自动删除缓存。
- R3/R4：保存成功后才切换选择和镜头；保存返回失败或抛出异常均恢复旧数据，保留原界面状态。
- R5：成功导入统一清理焦点、搜索、筛选菜单临时状态和节点拖动，再适应画布。

原有失败断言已保留并通过，另新增首次缓存加载、资料弹窗头像与关系 ID 转义检查。Pages 和 PR 工作流均已加入发布专项，不再仅依赖普通 `npm test`。

### R1：头像字段可注入 HTML 属性（原高优先级，已修复）

位置：`src/core.js` 的 `renderNodes`、`openDrawer`；导入校验在 `src/graph-domain.ts`。

复现：把头像设为以 HTTPS 开头、包含双引号与额外事件属性的字符串。校验目前只检查协议前缀，随后渲染把头像直接拼进 `innerHTML` 的 `src` 属性。测试确认生成的标记中出现了注入的事件属性；未在真实浏览器中执行攻击脚本。

影响：导入他人提供的 JSON 或手工填写恶意头像时，可能形成脚本注入。静态网站和“只有作者能改主分支”不能消除访客本地导入的风险。

建议：通过 DOM 属性设置头像地址，禁止不可信字符串参与 HTML 属性拼接；全面检查同类 ID/属性拼接，补上属性转义和 URL 校验用例，不能只拦一个测试字符串。

### R2：损坏的缓存能替换有效图谱（原高优先级，已修复）

位置：`src/core.js` 的 `load`、`restoreFromStorage`。

复现：IndexedDB 返回 `{nodes:[{id:'broken'}],edges:[]}`。恢复逻辑只检查两个数组即替换正式图谱，缺坐标、名称等结构仍被接受。专项测试对此失败。

影响：过期或损坏缓存可能造成不可见节点、渲染异常；localStorage 的加载也需要同等审查。

建议：缓存恢复复用共享结构校验；无效缓存保留可用的内嵌数据并给出可恢复提示。不要自动删除用户缓存或误报恢复成功。

### R3：导入存储失败没有完整恢复界面状态（已修复）

位置：`src/data-transfer.js` 的导入处理。

复现：已有选择、缩放和平移、正在建立关系时，让 `save()` 返回 false。数据对象会恢复，但选中人物、镜头、关系操作已提前重置。

影响：提示“原有数据未被覆盖”却丢失操作上下文。建议保存成功再切换状态，或完整回滚。

### R4：意外存储异常时没有回滚导入数据（已修复）

位置：`src/data-transfer.js` 的导入处理。

复现：故障注入让 `save()` 拒绝 Promise。导入先替换了内存数据，异常进入外层 catch 后仍保留新数据，却提示原有数据未覆盖。

边界：当前正常 `save()` 实现对常见 IndexedDB/localStorage 异常会返回 false；此用例模拟未预期异常，不代表正常保存必然抛出。仍应保证事务式回滚与提示一致。

### R5：成功导入可能残留旧搜索聚焦（已修复）

位置：`src/data-transfer.js` 的导入处理。

复现：先搜索聚焦某人物，再导入仍包含相同人物 ID 的备份。关系筛选被清除，但 `focusId` 和搜索词未清空；既有渲染只在 ID 不存在时自动清理，故仍可能显示局部图。

建议：导入成功统一清除焦点、搜索、临时菜单选择和拖动状态，再执行适应画布。补充相同 ID 与不同 ID 两类用例。
